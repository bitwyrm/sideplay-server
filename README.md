# Sideplay Server

FastAPI backend for Sideplay. It handles user accounts, OAuth linking for Spotify/YouTube, playlist sync, track normalization to canonical YouTube IDs, and serving cached media/thumbnail files.

This repo contains two services:
- `core.py`: main API service on port `5000`
- `media_service.py`: background media fetch/convert service on port `7000`

## Persistent Storage Root

All runtime artifacts are stored under a single configurable root:

- env var: `SIDEPLAY_DATA_ROOT`
- default: `./data` (resolved to an absolute path)

Artifacts written there include:
- SQLite DB (`sideplay.sqlite`)
- media files (`media/`)
- thumbnails (`thumbs/`)
- OAuth token caches (`oauth/spotify/`, `oauth/google/`)
- normalization cache map (`normalize_map.json`)

## What It Does

- Account auth with session tokens
- Link/unlink external Spotify and YouTube accounts
- Discover/search tracks and playlists across providers
- Normalize tracks to a YouTube canonical ID
- Build and maintain per-user library + local playlists
- Download and cache media (`.webm`) and thumbnails (`.webp`)

## Project Layout

- `core.py` main FastAPI app (mounts routers + static GUI)
- `media_service.py` media worker API (`/ensure-media`)
- `helpers/` API routers and shared setup/db code
- `spotify_lib.py` Spotify provider integration
- `yt_music_lib.py` YouTube Music + YouTube Data integration
- `static/gui.html` simple GUI entrypoint
- `<SIDEPLAY_DATA_ROOT>/` runtime state (SQLite DB, oauth token caches, media blobs)

## Runtime Requirements

- Python 3.11+
- Redis on `localhost:6379`
- `ffmpeg` in PATH
- `yt-dlp` in PATH
- OAuth credential JSON files in repo root (not committed)

## Run

Start Redis first.

Terminal 1 (main API):
```bash
python core.py
```

Terminal 2 (media service):
```bash
python media_service.py
```

- API base: `http://127.0.0.1:5000`
- Media worker base: `http://127.0.0.1:7000`
- GUI: `http://127.0.0.1:5000/`

## Data + State

- SQLite DB: `<SIDEPLAY_DATA_ROOT>/sideplay.sqlite`
- OAuth token caches:
  - `<SIDEPLAY_DATA_ROOT>/oauth/spotify/<spotify_user_id>.json`
  - `<SIDEPLAY_DATA_ROOT>/oauth/google/<google_sub>.json`
- Media cache: `<SIDEPLAY_DATA_ROOT>/media/<youtube_id>.webm`
- Thumbnails: `<SIDEPLAY_DATA_ROOT>/thumbs/<youtube_id>.webp`

## API Overview

Auth / account:
- `POST /sign-up`
- `POST /login`
- `POST /logout`
- `POST /account/reset-username`
- `POST /account/reset-password`
- `DELETE /account`

OAuth and external accounts:
- `GET /oauth/spotify/init`
- `GET /oauth/spotify/callback`
- `GET /oauth/youtube/init`
- `GET /oauth/youtube/callback`
- `GET /external-accounts`
- `POST /external-accounts/unlink`

Playlists:
- `POST /playlists/link`
- `GET /playlists` (local + linked)
- `GET /playlists/{playlist_id}`
- `POST /playlists/local/create`
- `POST /playlists/local/{playlist_id}/update`
- `DELETE /playlists/delete/{playlist_id}`

Library:
- `GET /library`
- `POST /library/add-track`
- `POST /library/remove-track`

Search:
- `POST /search/tracks`
- `POST /search/playlists/spotify`
- `POST /search/playlists/youtube`
- `GET /capabilities` (credential/access flags for UI adaptation)

Sync + media:
- `POST /sync-library` (streams JSONL progress)
- `GET /tracks/{youtube_id}/media`
- `GET /tracks/{youtube_id}/thumbnail`
- `POST http://127.0.0.1:7000/ensure-media` (internal worker endpoint)

## Auth Model

Most protected API endpoints expect a `session_token` request header. Tokens are generated by `POST /login` and stored in the `sessions` table with expiration.

`OPEN_ACCESS` controls whether selected read/search endpoints allow anonymous access:
- env var: `OPEN_ACCESS`
- accepted true values: `1`, `true`, `yes`, `on`
- default when unset: `false`

`POST /sign-up` defaults and validation:
- `username`: 3-64 chars (leading/trailing whitespace trimmed)
- `password`: 8-128 chars
## Sync Flow

`POST /sync-library`:
1. loads linked/local playlists for the authenticated user,
2. normalizes all tracks to canonical YouTube IDs,
3. upserts into `tracks` and `user_library`,
4. asks media service to ensure missing files,
5. streams status lines (`application/jsonl`) until done.

Media worker request shape (internal):
```json
{
  "tracks": [
    {
      "youtube_id": "string",
      "song_name": "optional string",
      "artist": "optional string",
      "album": "optional string"
    }
  ]
}
```

## Notes

- The media service currently expects a local `cookies.txt` file for `yt-dlp` downloads.
- Redis is used for caching search results and playlist track payloads.

## Podman / Docker Compose

Reference sample aligned to this repo's current compose setup:

```yaml
version: "3.9"

services:
  sideplay-server:
    image: sideplay-server:latest
    container_name: sideplay-server
    restart: always
    environment:
      SIDEPLAY_DATA_ROOT: /var/lib/sideplay
      SPOTIFY_CREDENTIALS_FILE: /creds/spotify-credentials.json
      GOOGLE_CREDENTIALS_FILE: /creds/google-credentials.json
      YT_HEADERS_FILE: /creds/headers.json
      YTDLP_COOKIES_FILE: /creds/cookies.txt
      OPEN_ACCESS: "true"
    volumes:
      - ./sideplay-data/data:/var/lib/sideplay
      - ./sideplay-data/creds:/creds:ro
    networks:
      hosted-services:
        aliases:
          - sideplay-server

networks:
  hosted-services:
    external: true
```

Notes:
- Keep `./sideplay-data/data` persisted so DB/media/oauth caches survive restarts.
- Keep `./sideplay-data/creds` mounted read-only.
- Set `OPEN_ACCESS` to `"false"` in production if you want auth-gated read/search endpoints.
